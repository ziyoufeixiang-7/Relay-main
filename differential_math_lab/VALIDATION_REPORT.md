# 差动电流数学验证报告

## 1. 验证边界

本报告只验证复相量数学，不启动 API、不写节点、不访问 FPGA、不读取 DI，也不代表实际保护或昂立硬件试验。

现有代码对照使用的是 `RelayProtection/calc/diff.py` 当前工作区版本。新正向模型使用以下明确假设：

- ABC 相序；
- 通道顺序 Ia/Ib/Ic 和 Ix/Iy/Iz；
- 两侧 Kp 都为 1；
- 动作量 `Id=|J1+J2|`；
- 制动量 `Ir=|J1-J2|/2`；
- 数学输入 `Id=0.5、Ir=1.0`，单位保持为调用者口径；
- Yd11、Y 侧校正按 M1/M0 解释；
- Yy12、Y 侧校正按 legacy 单相经验可解释的 M11/M11 解释。

最后两项是为了审查现有昂立经验分支而建立的兼容假设，不是所有 Yd11/Yy12 保护的通用配置。

## 2. 新正向模型验证

### 2.1 矩阵

- M0 与单位阵逐项相等；
- M1 与 SEL 公布的系数逐项相等；
- M1…M12 对 `[1,1,1]` 的输出为 0；
- 正序旋转 `+n×30°`，负序旋转 `-n×30°`；
- M0…M12 的逆/伪逆均完成正向闭环；
- 所有 13×13 两侧矩阵组合、七种相别均完成生成—正算闭环。

### 2.2 方程

测试覆盖：

- 五种 Id 枚举及全部已实现 Ir 字面公式；
- ABB 型 `K=2、Id=3、Ir=1` 的同向内部故障支路；
- `max` 制动的上下两个相对极性区间；
- 两绕组 `imax-sum` 字面退化及 `sqrt-cos` 支路；
- 平方坐标使用 `Ie²`；
- 不可达点、错误方程配对、负制动量和 NaN 被拒绝。

### 2.3 通道、模式和单位

- A/C/B 换序及单相 CT 反极性能正反闭环；
- `id_sum`、`id_diff` 及平方型动作量的穿越状态 Id 均为 0；
- 残流的 I0/3I0、换序和逐相极性正反闭环；
- 谐波百分比按电流谱幅值计算，平方 Id 方程不会把 15% 错算成 2.25%；
- 2I 多源并联拆分后，合流电流恢复目标值；
- RMS/峰值转换是显式可逆函数，核心生成器没有隐式 $\sqrt2$。

## 4. 现有 6I 单相代码审查

对 Yd11 和 Yy12，枚举 `none/y-side/delta-side × zeroSequenceCorrection false/true × A/B/C`，每组 18 例：

| 接线组 | 一致 | 不一致 |
|---|---:|---:|
| Yd11 | 15 | 3 |
| Yy12 | 18 | 0 |

Yd11 的三个不一致全部是 `phaseCorrection=y-side` 且 `zeroSequenceCorrection=true`：

| 相别 | 最大 Id 误差 | 最大 Ir 误差 |
|---|---:|---:|
| A | 0.75 | 0.375 |
| B | 0.75 | 0.375 |
| C | 0.75 | 0.375 |

原因是 M1 已在 Y 侧完成相位补偿和零序消除，现有经验分支却对未匹配的 d 侧又追加了一个零序对消通道。

用户现场已经确认 Yd11/Yy12 的 6I 单相试验能通过，这是最有价值的外部证据；仓库中没有对应的完整起始 JSON、昂立六路幅相导出或保护抓波。因此本报告只证明当前输出与所列假设模型是否一致，不能替代现场结论。

另一个必须保留的限制是：现有单相经验函数只接收 `low_clock`，忽略 `high_clock`。本节所有 Yd11/Yy12 用例都是 `highClock=0`；当高压侧钟点非零时，现有单相分支没有按 `low-high` 计算相对钟点，本报告不判定其正确。

## 5. 现有 6I 多相代码审查

只比较 `phaseCorrection=y-side、zeroSequenceCorrection=false`：

| 接线组 | 相别 | 结果 | 最大 Id 误差 | 最大 Ir 误差 |
|---|---|---|---:|---:|
| Yd11 | AB | 不一致 | 0.721688 | 0.360844 |
| Yd11 | BC | 不一致 | 0.721688 | 0.360844 |
| Yd11 | CA | 不一致 | 0.721688 | 0.360844 |
| Yd11 | ABC | 不一致 | 0.207956 | 0.031909 |
| Yy12 | AB | 不一致 | 0.288675 | 0.577350 |
| Yy12 | BC | 不一致 | 0.288675 | 0.577350 |
| Yy12 | CA | 不一致 | 0.288675 | 0.577350 |
| Yy12 | ABC | 一致 | 浮点舍入级 | 浮点舍入级 |

Yd11 的直接原因是：单相经验分支由 low clock 构造出与 M1/M0 相容的通道关系，多相分支却把 high clock 0 用于 Y 侧，等效走 0° 路径。Yy12 的 AB/BC/CA 则没有真正逆解 M11/M11；ABC 因平衡正序共同旋转后幅值不变而偶然一致。

这正好解释了“单相照昂立能测，多相没有对过且现场不通过”的现象。它仍不是对具体保护的最终修复公式；最终矩阵必须由 DUT 设置确认。

## 7. 还缺少的外部验证

若要把数学结果升级为可上线结论，需要至少采集：

1. 被测保护厂家、型号、固件；
2. 差动定值页中的 TAP/参考电流、矩阵或接线组补偿设置；
3. CT ratio、星点、相序、通道和极性；
4. 昂立在同一设置下 A、AB、ABC 的完整六路 RMS 幅值和角度；
5. 保护实际显示的每相 Id/Ir；
6. 当前 API 写 FPGA 前的峰值以及保护端子实测 RMS。

将这些数据固化为 golden vectors 后，才能判断是矩阵侧别/角度问题、RMS/峰值问题、Kp/TAP 问题，还是前端相别语义不同。
