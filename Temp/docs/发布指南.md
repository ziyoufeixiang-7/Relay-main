# 发布指南

> 详细原理见《部署与OTA更新手册.md》。所有命令在项目根目录执行。

## 改了什么，就怎么发

| 改了什么 | 在哪操作 | 命令 |
|----------|----------|------|
| 后端 Python 代码 | 树莓派 | `./deploy/build.sh` 然后 `./deploy/publish.sh` |
| 只改前端网页 | 树莓派 | 替换 `deploy/web/index.html` 后 `./deploy/publish-web.sh` |
| 只改前端网页 | Windows | `.\publish-web.ps1`，见《Windows前端发布.md》 |

- `build.sh` 编译约 15~30 分钟；只重打包用 `--pack-only`（秒级，需编译过一次）
- 前端发布**不需要编译**，直接上传 html，服务器用已有后端包重新合包

## 发布脚本会做什么

1. 查服务器当前版本并显示
2. 选新版本号：`1` 补丁+1（默认）/ `2` 次版本+1 / `3` 主版本+1 / `4` 手动输入
3. 填更新说明 changelog（可留空）
4. 上传文件 + 服务器端 SHA-256 校验
5. 服务器端合包成 `relay12-vX.Y.Z.tar.gz`（设备实际下载的就是它）
6. 最后一步原子更新 `version.json`，再回读验证

全程无需手动改任何文件，版本号以**服务器上的为准**。

## 云端目录

```
http://47.98.48.17/update/relay12/
├── version.json                    # 设备"检查更新"读取
├── relay12-vX.Y.Z.tar.gz(.sha256)  # 设备更新包（合包产物）
├── backend.tar.gz(.sha256)         # 后端发布包
├── index.html(.sha256)             # 前端页面
└── init-pack.tar.gz                # 新设备初始化包（publish_init.sh 上传）
```

## U 盘离线更新

服务器上的 `relay12-vX.Y.Z.tar.gz` 和 `.sha256` 两个文件拷到 U 盘根目录，
插入设备 → 系统设置 → 扫描 USB → 选择更新。

## 注意

- **首次发布**（或换新机型目录）必须先在树莓派完整发布一次 `./deploy/publish.sh`，之后才能用仅前端发布
- 发布失败时设备不受影响：`version.json` 是最后一步才更新的
- 设备更新出问题可在界面点"回滚"恢复上一版本
