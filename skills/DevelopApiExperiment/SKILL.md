# DevelopApiExperiment 技能指南

作为一名专业的继电保护领域专家和高级 AI 开发助手，当你接到开发一项新的实验 API（继承自 `BaseApi`）的任务时，你**必须**严格遵循本文档中定义的流程、架构红线以及数据流转规范。

## 1. 强制交互工作流 (Mandatory Workflow)

在编写任何实际的 Python 代码之前，你必须按顺序完成以下交互与规划：

### 第一步：理论研究与编写实验大纲
当接到一个新的继电保护实验项目（如“差动保护”、“距离保护”等）时，你必须首先化身为**专业的继电保护领域专家**。
- 利用你丰富的背景知识，结合数学推导和专业领域公式，撰写一份“具体如何进行该项测试”的**实验原理与方法文档**。
- 这份文档必须保存在与前端 API 协议文档相同的目录中，为后续的逻辑开发奠定坚实的理论基础。

### 第二步：理解与备注通信协议
仔细阅读现有的前端与后端的 API 通信协议文档。结合你在第一步中推导的实验理论，通过交互的方式在协议文档中详细**备注好整体实验的控制逻辑和参数定义**。

### 第三步：交互式问答 (/grill-me)
你**必须**主动向用户发起深入的 `/grill-me` 实验细节挖掘：
- **重中之重**：与用户详细讨论实际的**继电保护测试逻辑**，并探讨“如何将复杂的继电保护测试逻辑巧妙地拆解并映射到我们的底层状态机节点（`ApiNodeData`）上”。
- **参数单位排雷**：仔细确认 `params` 字典里前端传来的各种非标准物理量（如整定值、电流定值等），明确它们是**幅度值 (Amplitude)** 还是**有效值 (RMS)**。这决定了后续是否需要进行 $\sqrt{2}$ 的转换。

### 第四步：规划与确认
起草实施计划，清晰地规划出将要构建的状态机节点序列（`ApiNodeData`），以及你打算如何利用回调函数进行状态控制与报告生成。**等待用户的审核与批准**。

### 第五步：生成代码
在获得批准后，编写继承自 `BaseApi` 的具体实验类 `Api*Test.py`，并在 `api.Registry.py` 中进行挂载注册。

## 2. EngineCtrl 沙盒机制与边界红线

在 API 开发中，你只能通过 `self.ctrl` (即 `EngineCtrl` 实例) 与底层硬件进行交互。必须严格遵守以下红线：

> [!WARNING]
> **绝对禁区**：API 层代码**绝对不允许**导入、实例化或触碰 `USENode`。将节点编译为 FPGA 帧并组装 `USENode` 是 `EngineCtrl` 内部完全私有的黑盒操作。你的职责到组装 `ApiNodeData` 为止！

### 允许调用的接口 (`self.ctrl` 暴露的方法)
- `self.ctrl.upsertNodes(apiNodes: Dict[int, ApiNodeData]) -> bool`：将你组装好的状态机字典下发给底层的 FPGA 引擎。
- `self.ctrl.trigNode(nodeId: int) -> bool`：强制底层引擎立即跳转或触发特定的节点 ID 开始执行。
- `self.ctrl.sendReport(data: dict)`：向前端回传自定义的实验报告（如跳闸时间、定值评价等）。
- `self.ctrl.sendError(msg: str)` / `self.ctrl.sendStop()`：遇到致命错误时中断实验。

### 回调机制的运用 (逆向接收消息)
你的 API 类可以通过重写以下方法，逆向接管底层的进度或前端的指令：
- `onUpdate(nodeId: int, tick: int, hw_ts: int)`：用于检测特定节点的执行进度。
  - **动态跳转**：如果预先写死的节点跳转逻辑无法满足需求，你可以在这里根据 `tick` 结合 `trigNode` 实现高级动态状态机跳转。
  - **数据收集**：在此处收集回传的高精度时标和进度，这是最终**生成实验结果报告**必不可少的素材。
- `onDi(di: int, hw_ts: int)`：用于检测开关量输入（例如继电保护装置的跳闸动作）。
  - **跳转与记录**：一旦检测到变位，立刻实现状态流转，其提供的高精度跳闸时间数据是评估动作特性的核心依据。
- `onWebCommand(msg: Dict)`：用于接收实验运行途中前端发来的异步手动干预指令（例如：前端点击了“手动切换状态”或“静态调整输出电压”的滑块）。

## 3. 物理值 -> 寄存器 -> 物理值的完整流转

此环节是写对控制逻辑的根本，任何数学和格式上的疏忽都会导致输出严重的波形错误。

### A. 静态与动态数据结构的终极铁律
对于 `ApiNodeData` 中的 `base` (起始状态)、`reset` (重置状态) 以及 `steps` (步进增量) 这三个字典：
> [!IMPORTANT]
> **它们必须且一定全部是幅度值 (Amplitude)**，并且嵌套结构必须高度统一如下：

- **第 0 层 (直流)**：`[直流幅度 (V/A), 频率 (Hz)]` *(注：0层的相位字段用来存放频率)*
- **第 1-64 层 (交流谐波)**：`[交流谐波幅度 (V/A), 相位 (度)]`

**⚠️ 有效值 (RMS) 转换红线**：
如果你的实验逻辑接收到前端下发的特定参数是**有效值 (RMS)**，API 层**必须**手动引入高精度的 `math.sqrt(2)`（约 1.414），将其乘以有效值计算出真正的峰值（幅度值），然后再填入上述的底层数据结构字典中！

### B. 数据下发流转路径 (Downward Flow)
1. **API 层组装**：通过你的业务逻辑，组装好含有**纯物理幅度值**的字典。
2. **底层转换**：API 层调用基类的转换器 `self.physDictToReg(phys_dict, is_delta)`。
3. **黑盒映射**：该方法内部会遍历每一个通道和层级，自动调用系统核心的 `calib.PhysToReg(hw_ch, l, amp, phase, is_delta)` 函数。
4. **加载运行**：经过转换的**寄存器值**会被存入 `ApiNodeData`，最后由你调用 `upsertNodes` 下发给 FPGA。

### C. 数据回传流转路径 (Upward Flow)
回传是完全自动的，**API 开发者无需在此过程中做任何干预**：
1. 实验运行中，`EngineCtrl` 底层触发更新（收到 FPGA 发送的中断 tick）。
2. `EngineCtrl._handleValueUpdate` 会读取执行中的节点数据并动态计算当前的寄存器累加状态（`self.state`）。
3. `EngineCtrl` 随后调用 `self.sendValueUpdate(target, self.state)` 准备向 WebSocket 推流。
4. 在打包给前端的 JSON 前，底层系统会利用字典推导式自动调用 `calib.RegToPhys(ch, l, regAmp, regPhase)`，将当前的寄存器值**逆向还原为物理幅度值、频率和相位**，并发送给前端展示。
