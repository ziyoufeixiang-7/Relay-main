# 静态多频点幅值校准使用说明

## 1. 本次范围

补偿静态输出各交流分量的频率幅值响应，主要用于谐波实验。交流频率表上限为 3 kHz，优先测量和验收 1 kHz 以内。64 个交流层及 FPGA 协议保留，不要求测满全部层的可能频率。

自动校准同时支持 **RIGOL DM858/DM858E、DM3058/DM3058E、DM3068 和 Agilent/Keysight 34410A、34461A**，根据 `*IDN?` 自动识别，不需要前端新增型号参数。DM3068 的接线、命令集与档位适配见第 13 节；34410A 的适配和 USB 实机验证见第 16 节；DM3058/DM3058E 与 DM3068 的规约差异见第 17 节；34461A 的适配及电流端子要求见第 18 节。

`USEEngine.py`、各实验 API 的扫描控制及原 `calibration.json` 实测系数均未修改。新频率表提交后，后续实验使用新快照；运行中的实验不换系数。

**所有纯静态实验都使用新表，不只限于 `harmonic_test`。频率扫描和重复固定寄存器增量不在本次范围内。** 为避免“扫描起点用新表、步进用旧系数”，含寄存器 Sweep 的实验整场使用去掉曲线的旧系数快照，包含复归、起点、扫描、终点等待和前端反算。`isDelta=True` 本身仍使用旧文件的固定 AC 系数。已有 Sweep 不属于新表校准范围。静态准确性也不等于相位频响、削顶或多谐波叠加失真已得到修正。

| 实验 | 本次校准选择 |
| --- | --- |
| 差动（含谐波制动）、线路、阻抗、反时限、时间测量 | 静态输出使用频率表；业务计算、DI/DO、节点出口和报告逻辑不变 |
| `ApiScanTest` 的 `sys.mode=0` | 静态手动模式使用频率表，包括谐波静态在线更新 |
| `ApiScanTest` 的非 0 模式 | 整场旧系数，包括 RESET、正向/反向 Sweep |
| 状态序列全部节点为 `STATIC` | 使用频率表 |
| 状态序列至少一个节点为 `SWEEP` | 整场旧系数，包括其中的 STATIC 和隐藏中转节点 |
| 滑差实验 | 整场旧系数，避免跨搜索轮次混用 |
| 原始寄存器 `ApiBaseTest` | 仍绕过物理值校准，原样执行；显示反算也保留旧系数 |

这里“旧系数”是当前 `calibration.json` 的已校准系数，不是默认出厂系数；运行期间不会切换快照。以后增加新的寄存器扫描 API 时，需同步维护 `BaseApi._usesLegacyCalibration()` 的选择规则。

## 2. 物理值与层定义

实验物理字典中的交流幅值始终是峰值，不是 RMS，公共转换不会再乘根号 2。

| 层 | 第一个数 | 第二个数 | 使用的校准 |
| --- | --- | --- | --- |
| 0 | DC 值 | 本通道基频 f0，Hz | 旧 DC 系数和零点偏置 |
| 1～64 | 该次交流分量的峰值 | 相位，° | 第 n 层使用实际频率 n×f0 的 AC 系数 |

例如 API 电压通道 0：

```json
{
  "0": {
    "0": [0, 50],
    "1": [80, 0],
    "3": [8, 30],
    "5": [4, 60]
  }
}
```

交流分量分别使用 50、150、250 Hz 的系数，峰值分别是 80、8、4 V。第 0 层不是 0 次交流波形，也不是基波幅值。

转换会先读取整通道的基频，因此字典顺序无关。交流/直流/谐波实验的静态在线更新会先合并最近一次已接受的物理设定，再编译完整目标节点；只修改第 0 层频率时，所有已设定非零谐波按新频率重新补偿。不会以尚未到达的硬件回报作为下一次更新的输入；转换失败也不提交新的设定缓存。

**纯静态状态序列和时间测量支持节点间继承。** `StaticCalibration.py` 按真实跳转关系推导各通道基频和交流分量，入口继承节点 0 的 50 Hz/零交流状态，不依赖数组顺序，也不依赖编译时的实时回报。隐藏延时节点保持继承语义；循环按稳定后的可能状态分析。仅改基频时，会补写需要重新补偿的继承谐波。

如果分支汇合后有多种继承频率，而目标节点要写非零交流分量，须在目标节点明确提供第 0 层。如果改频时某谐波可能继承不同幅值/相位，须明确提供该谐波层。程序会报告节点、通道和原因，不会猜测参数。只是继承、不需要重新编码的分支不受此限制。新表为空或整场使用旧系数的扫描实验不进入此分析。

## 3. 参数文件及插值

原文件 `RelayProtection/config/calibration.json` 继续使用：

```text
"硬件通道号": [bias, factorDc, factorAc]
```

新文件是同目录下的 `calibration_ac_frequency.json`，初始 `channels={}`，表示所有通道仍使用旧 AC 系数。某通道没有曲线时也同样回退，不会影响已校准的其他通道。

格式示意如下，数字只用于解释，**不是可直接用于设备的实测系数**：

```json
{
  "schemaVersion": 1,
  "channelNumbering": "fpga",
  "amplitudeConvention": "peak",
  "interpolation": "linear_factor",
  "outOfRangePolicy": "clamp_warn",
  "channels": {
    "0": {
      "points": [
        {"freqHz": 55, "factorAc": 0.95},
        {"freqHz": 155, "factorAc": 1.02},
        {"freqHz": 1000, "factorAc": 1.10}
      ]
    }
  }
}
```

频率表的通道号是 FPGA 号，而校准命令的 `ch` 是前端 API 号：

| API 通道 | 物理量 | FPGA 通道 |
| --- | --- | --- |
| 0、1、2 | Ua、Ub、Uc | 0、2、4 |
| 3、4、5 | Ux、Uy、Uz | 6、8、10 |
| 6、7、8 | Ia、Ib、Ic | 1、3、5 |
| 9、10、11 | Ix、Iy、Iz | 7、9、11 |

`factorAc` 是从原始寄存器标度获得的**绝对补偿系数**，不是再乘旧 `factorAc` 的相对系数：

$$
F(f)=F_0+(F_1-F_0)\frac{f-f_0}{f_1-f_0}
$$

$$
A_{reg}=\operatorname{round}(A_{peak}\,F(nf_0)\,S)
$$

S 为既有电压/电流寄存器标度。相位仍按原方式加 180°；DC 仍按 `DC×factorDc+bias` 编码。

表外频率使用最近端点系数并记录警告，不做外推，也不保证表外精度。DDS 频率会量化到寄存器步长，保存和校准计算使用实际量化频率；端点允许一个 DDS LSB 的差异。

加载时整体验证两份文件。重载错误不发布半套参数；初次加载完全没有有效参数则拒绝物理值转换。写入采用临时文件、fsync 和原子替换；自动校准提交前保存对应旧文件 `.bak`，其他通道保持原样。

## 4. 校准命令

保留原入口 `cmd="autoCal"`，不要把它写成实验的 `cmd="start"`。原界面不传新参数时仍执行 DC/50 Hz 四步校准。

先认证：

```json
{"cmd":"autoCal","action":"auth","password":"100200"}
```

### 4.1 原 DC/50 Hz 四步校准

```json
{"cmd":"autoCal","action":"start","ch":0,"currMode":0}
```

依次测量原始交流 50 Hz、DC 零值、正 DC、负 DC；拟合后仅修改旧文件中选定通道的三项参数。电压参考值为交流 57.735 V RMS、DC ±100 V；电流为交流 0.5 A RMS、DC ±0.5 A。

如果该通道已经有频率曲线，静态 AC 仍优先使用曲线，旧四步校准不会清除或覆盖它。功放或测量链改变后，应重新完成频率校准，不能认为只重测旧 50 Hz 系数就更新了整条频响曲线。

### 4.2 多频点 AC 校准

```json
{
  "cmd": "autoCal",
  "action": "start",
  "ch": 0,
  "calibrationMode": "ac_frequency",
  "frequenciesHz": [47,55,105,155,205,255,305,405,505,755,1000],
  "referenceRms": 57.735,
  "settleMs": 5000,
  "sampleMs": 10000,
  "maxErrorPct": 2.0
}
```

提供 `frequenciesHz` 而省略 `calibrationMode` 时，也选择 `ac_frequency`。显式写 `legacy` 则仍执行旧四步行为。

不提供 `frequenciesHz` 时，默认：

```text
47, 55, 105, 155, 205, 255, 305, 405, 505, 755, 1000,
1505, 2005, 2505, 3000 Hz
```

这组频点可以避开工频附近并逐渐稀疏；若只需要 1 kHz，使用上面的自定义列表即可。47/55 Hz 夹住 50 Hz，不把 55 Hz 实测值标成 50 Hz。应另外验证 50 Hz 插值效果。

| 参数 | 含义和缺省 |
| --- | --- |
| `ch` | API 通道 0～11；一次只校准一路 |
| `calibrationMode` | 支持 `legacy`、`ac_frequency`；未增加单独 `dc` 模式 |
| `frequenciesHz` | 至少两个不同频点；可为小数、非等间隔，排序去重后量化；自动 AC 校准接受 20～3000 Hz |
| `referenceRms` | 交流采样参考 RMS；电压缺省 57.735 V，电流缺省 0.5 A；仅这里内部转换一次峰值 |
| `settleMs` | 每点建立时间，缺省 5000 ms，最少 3100 ms |
| `sampleMs` | 每点基本采样窗口；电压缺省 10000 ms，电流 30000 ms；必须为正。读数不足时允许有限补采样，见下文 |
| `minSamples` | 最少有效读数，缺省 5，必须是 ≥2 的整数 |
| `maxErrorPct` | 候选曲线逐点验证的误差上限，缺省 2%；不是仪表或输出精度的承诺 |
| `visaResource` | 可选，指定 VISA 资源；否则按旧版优先选择 USB/GPIB。连接以非空 `*IDN?` 回复为准，型号决定后续配置 |
| `currMode` | 电流测量方式：0 为外接采样电阻测电压，非 0 为仪表直接测电流；电压通道忽略此项 |
| `shuntOhms` | 电流电阻采样的阻值，缺省 0.075 Ω |
| `shuntProfile` | 可选外部实测阻抗模型，见下节；不会由本程序自动校准电阻 |
| `loadDescription` | 可选，记录测量负载说明，不参与计算 |

额外前端字段不读取、不要求移除。基本采样窗口结束后，如果还未达到 `minSamples`，最多再补采样 `max(5, minSamples)` 秒；正在执行的一次 VISA 查询仍受 5 秒超时约束。补采样后仍不足则失败，不把非法读数当作校准结果。这个规则也用于旧版默认 3 秒窗口的独立校验，避免慢速积分或 USB 延迟导致正常仪表始终凑不够 5 个读数。

流程：每点关闭功放 → RESET/START → 配置仪表 → 写明确基频与原始单一正弦 → 等 ACK → 开功放、建立、采样 → 关闭功放。原始目标和测量平均值之比得到候选系数，然后用候选曲线重新输出每个频点验证。所有点合格才整表提交，只改选定通道；停止/异常/验证失败不提交。

## 5. 电流测量链

`currMode=0` 时，电流由电压读数除以采样阻抗得到。没有外部阻抗模型时仅假设电阻在交流下仍为 `shuntOhms`，这不代表已证明高频误差很小。

可提供实测交流阻抗模值，单位 Ω：

```json
{
  "shuntProfile": {
    "dcOhms": 0.075,
    "points": [
      {"freqHz": 47, "ohmsMagnitude": 0.075},
      {"freqHz": 1000, "ohmsMagnitude": 0.0752},
      {"freqHz": 3000, "ohmsMagnitude": 0.0755}
    ]
  }
}
```

以上也是格式示意，不是设备实测值。`dcOhms` 优先于 `shuntOhms`；交流模值线性插值，不允许请求模型覆盖范围外的频率。量程依据实际电阻/阻抗与参考电流计算。

直接测电流必须正确使用电流输入端和保险丝。自动多频点直测限制 DM858/DM3068 ≤7 A RMS，DM858E ≤3 A RMS；这是程序保护边界，不是建议的校准参考幅值。默认电流校准仍为 0.5 A RMS、原九点校验最大设定仍为 2 A，新增 DM3068 不提高输出电流。DM858 的 3 A 命令会改用其实际 10 A 量程，DM858E 则保留 3 A。手册中的高电流通断时间与测量不确定度仍需遵守。[DM858 数据手册](rigol_dm858/DM858_DataSheet_CN.pdf)、[DM3068 数据手册](../../../DM3068_DataSheet_CN.pdf)

## 6. 验证、停止和返回消息

独立验证频率曲线：

```json
{
  "cmd":"autoCal",
  "action":"verify",
  "ch":0,
  "calibrationMode":"ac_frequency",
  "frequenciesHz":[50,80,130,350,650,950],
  "referenceRms":57.735
}
```

省略 `frequenciesHz` 时验证本通道已存全部点；自定义验证点也至少两个，并须位于曲线覆盖范围内。独立 `verify` 只测量和报告误差，不保存新参数、不按阈值自动宣称硬件验收通过。可选未参与拟合的中间点验证插值。

停止：

```json
{"cmd":"autoCal","action":"stop"}
```

立即关闭功放并阻止后续输出；已经开始的 VISA 查询在超时或返回后有序结束，随后 RESET。仪表 I/O 在线程中执行，不占用 WebSocket 事件循环。校准与普通实验互斥，先停止实验再校准；前端断开或硬件保护停止也会要求结束校准。

保留 `authResult`、`calStatus`、`calError`、`verifyPoint`。`calStatus` 新增可选的 `stage`、`frequencyHz`、`ch`、`revision`。`verifyPoint` 中 `target` 是高 16 位量化后、反算出的物理目标；交流 `target/measured/requested` 是 **RMS**，`amplitudeConvention="rms"`，DC 是直接物理值。这与实验节点的峰值口径不同，不能混用。

校准提交成功时 `progress=100, stage="saved"`；独立验证结束为 `stage="verified"`；用户停止为 `stage="stopped"`，异常发送 `calError`。旧四步成功保持原 `progress=100` 行为。

## 7. 仪表与设备参数保护

DM858/DM858E 按用户实测反馈恢复旧版配置流程：发送 `CONF` 设置、DC 积分时间设置，等待 0.5 秒，再按原流程 `READ?` 采样。配置等待在 VISA 工作线程内，不阻塞停止处理。此旧路径不再添加 `*CLS`、`ABOR`、NULL、SCAL、触发设置。DM3068 使用原生自动触发和按测量功能取值的方式，见第 13 节；两个型号均不查询量程、积分时间、触发源或错误队列来阻断校准。

保留已经核对的型号命令适配：DM858/DM858E 的 DC 使用 20 PLC；DM3068 使用其支持的 10 PLC；未知旧仪表维持原 10 PLC。DM858 大电流用 10 A 档，DM858E 用 3 A 档。读数中的 NaN、inf 和 9.9E37 超量程标记仍不参与拟合；停止关功放、通信异常处理及拟合结果检查仍保留。具体档位和此次回退说明见第 12、13 节。

连接使用原有 `pyvisa.ResourceManager("@py")` 和 5 秒超时，以非空 `*IDN?` 回复确认连接；不再把型号白名单或 `*CLS` 配置写入当作连接前提。第 1 节列出的型号会被识别并使用专用配置；其他原来能连接的仪表，在旧 DC/50 Hz 校准/校验中保留旧 SCPI 命令路径（包括原 10 PLC 命令），不代表已验证其支持多频点功能。多频点流程要求识别为已适配型号。

VISA 枚举、打开、识别、配置及采样在线程执行；前端消息统一回到主事件循环发送。日志记录资源列表、实际 `*IDN?` 回复和每个候选资源的失败原因；配置阶段异常显示为校准/校验异常，不再笼统归为“找不到万用表”。

预热、负载、交流测量带宽、布线和干扰仍需人工确认。本程序不自动保证已预热 30 分钟，也未实现辅助频率读数、漂移阈值或自适应加密频点。[DM858 用户手册](rigol_dm858/DM858_UserGuide_CN.pdf)

- 升级/回滚保护清单包含两份校准文件。
- 打包包含空频率表模板，打包脚本拒绝发布非空设备曲线；已有设备实测表通过更新流程保留。
- `run_python_test.sh` 从正式 `calibration.json` 所在目录复制两份设备参数，默认 `/opt/RelayProtection/config/`。正式目录没有频率表时，明确写空表使用旧系数，不使用上传的开发机曲线。
- `.bak` 是校准提交时保留的前一份文件，不会自动回滚；需要恢复时停止服务，检查并恢复对应参数后重启。跨旧版本更新器的降级仍需另行备份两份文件。

### 旧机器第一次升级

旧机器没有 `config/calibration_ac_frequency.json` 是正常情况。执行完整构建时，更新包包含空频率表；设备端先解压更新包，再把旧机器的 `config/calibration.json` 复制到新目录。即使负责这次更新的是只认识旧文件的旧 `Updater.py`，也不会删除解压得到的新文件。因此第一次升级后，在默认安装位置可以看到：

```text
/opt/RelayProtection/config/calibration.json               原设备实测系数
/opt/RelayProtection/config/calibration_ac_frequency.json  新增空模板，channels={}
```

新文件缺失或 `channels={}` 都使用旧交流系数，DC 继续使用旧偏置和系数。旧前端不发送 `calibrationMode` 时，`start`/`verify` 仍执行原 DC/50 Hz 流程。只有明确请求多频点校验、而本通道还没有频率曲线时，才提示先校准该通道。无效 JSON 与“文件不存在”不同：损坏的文件会导致加载失败。

## 8. 本地验证与上机顺序

数学/配置/模拟仪表测试在 `RelayProtection/tests/test_calibration_frequency.py`；发布兼容性对照在 `RelayProtection/tests/test_calibration_compatibility.py`。后者按改造前公式独立计算期望值，并对实际实验生成的节点和编译帧进行比较。新增 `test_calibration_safety.py` 独立解码实际编译帧、模拟功放增益，并检查节点继承、连续更新和启动/停止时序。按照应用使用的 uvloop 运行所有 unittest：

```bash
PYTHONDONTWRITEBYTECODE=1 USE_REAL_HARDWARE=False .venv/bin/python - <<'PY'
import asyncio
import unittest
import uvloop
asyncio.set_event_loop_policy(uvloop.EventLoopPolicy())
suite = unittest.defaultTestLoader.discover('RelayProtection/tests')
result = unittest.TextTestRunner(verbosity=1).run(suite)
raise SystemExit(not result.wasSuccessful())
PY
```

## 12. 实测量程报错：恢复旧式设置与采样流程

现场反馈：`Calibration exception: DM858 range mismatch: 1.0 != 0.1`。这说明原新增校验比较的请求档位是 0.1、回读是 1.0；报错缺少测量功能，不能仅凭它断言单位是 V 还是 A，也不能断言仪表没有 0.1 档。

已核对 [RIGOL 官方编程手册](https://download.rigol.com/en/Manual/Digital%20Multimeters/DM858/DM858_ProgrammingGuide_EN.pdf) 3.10.3、3.10.4、3.10.11、3.10.12：

| 功能 | 支持的固定档位 |
| --- | --- |
| AC 电压 | 0.1、1、10、100、750 V |
| DC 电压 | 0.1、1、10、100、1000 V |
| AC / DC 电流 | 100 μA、1 mA、10 mA、100 mA、1 A，最高档 DM858 为 10 A、DM858E 为 3 A |

因此 `CONF:VOLT:AC 0.1`、`CONF:VOLT:DC 0.1` 和 `CONF:CURR:DC 0.1` 都有对应的手册档位，并非必须改为 1。1 V 档也能读取小于 0.1 V 的信号，但量程变化会影响分辨率/不确定度，不需要把读数再乘除 10。

用户要求直接沿用旧流程，最终实现**不是放宽范围后再严格检查**，而是取消新增的配置回读门槛及额外配置命令：设置 → 等待 0.5 秒 → 实际采样。不会因 `1.0 != 0.1`、NPLC/触发回读差异或错误队列产生本次新增的配置拦截。不改变多频点采集、校准系数计算、参数保存和设备停止保护。

模拟测试复现“请求 0.1 V，仪表内部选 1 V”：仍正常读取 0.0375 V，经原 0.075 Ω 分流电阻换算为 0.5 A，没有额外缩放；并断言配置阶段不发查询命令。尚未实机复测，也没有证据确认此前量程回读差异的仪表端原因。

## 13. DM3068 兼容支持

### 13.1 手册依据与连接

依据用户提供的 [DM3068 编程手册 ZIP](../../../DM3068编程手册.zip) 内 `DM3068_ProgrammingGuide_CN.chm`，核对了“通用命令集 → CMDSet / *IDN?”、“RIGOL 命令集 → FUNCtion / MEASure / TRIGger / CALCulate / RATE”、“兼容的 Agilent 命令集 → SENSe”及“编程准备 / Visual C++ / Visual Basic 示例”。量程、保险丝和交流频段另与 [DM3068 数据手册](../../../DM3068_DataSheet_CN.pdf) 第 6～8 页交叉核对。

推荐与原仪表一样连接后面板 **USB Device** 口。沿用 PyVISA 枚举和 USB/GPIB 优先顺序，支持指定已有 `visaResource`。LAN 可使用 VISA 的 `TCPIP0::<设备 IP>::INSTR` 资源；不要把仪表型号当成 VISA 地址。实际连接还依赖系统安装的 VISA 后端、USB 权限或对应网络支持。

若使用 RS232，手册要求命令以 `\r\n` 结束，程序对 `ASRL...::INSTR` 设置 CRLF 写终止符、LF 读终止符。沿用 VISA 默认 9600 波特、8-N-1，仪表端须设为相同参数；不自动扫描波特率或修改仪表串口设置。DM3068 的 USB/LAN 测量使用 LF 写入、LF 结束读取，与手册编程示例一致，不仅依赖通信后端的默认结束行为。DM858 不应用这次新增的型号专用终止符设置。

前端的认证、`start`、`verify`、`stop`、`ch`、`currMode`、频点和报告格式均不变。换表后自动按 `*IDN?` 识别，不需要重新生成或迁移校准文件。

### 13.2 命令集与采样

DM3068 的 RIGOL 原生命令集不同于 DM858，另支持 Agilent 和 Fluke 兼容命令集。现场电流、电压均复现 Agilent 兼容 `:READ?` 超时后，采样改用手册示例的原生 `FUNC/MEAS` 路径，不再发送 DM3068 的 `:READ?`。以下是 57.735 V RMS、200 V 档的配置示例，均在功放关闭期间完成：

```text
CMDSet AGILENT
SENS:DET:BAND 20       # 仅通过兼容设置命令保留中速交流滤波
CMDSet RIGOL
:FUNC:VOLT:AC
:MEAS MANU
:MEAS:VOLT:AC 3        # 原生量程编号 3 = 200 V，不是输出 3 V
:CALC:FUNC NONE
:TRIG:SOUR AUTO
:TRIG:AUTO:HOLD OFF
:TRIG:AUTO:INTE 0.2
```

以上注释仅用于说明，程序不发送注释。命令集切换后在 VISA 线程等待 0.1 秒，再发送该命令集的语法；配置完成等待 0.5 秒。直流在兼容设置阶段使用 `SENS:VOLT:DC:NPLC 10` 或 `SENS:CURR:DC:NPLC 10`，然后也切回 RIGOL 原生功能和量程设置。

保留这个短暂的兼容设置阶段是有依据的：手册明确说明原生 `RATE:...:AC` **只接受、不执行操作**；而原生 DC `RATE ... S` 是 100 PLC，不是原来的 10 PLC。因此不能为“全部原生”而使用无效交流速率命令或悄悄改变 DC 积分时间。兼容阶段不触发测量、不执行 `READ?`、不查询缓冲区；切回 RIGOL 后才进行采样。

设置 FPGA 输出、开功放并等待原有稳定时间后，每轮先发送 `:MEAS?`。原生这个指令返回的是 **TRUE/FALSE（有无新数据）**，不是电压电流值：FALSE 时不读取缓存、不增加样本数，稍后再查；TRUE 时才使用对应的 `:MEAS:VOLT:AC?`、`:MEAS:VOLT:DC?`、`:MEAS:CURR:AC?` 或 `:MEAS:CURR:DC?` 获取实际 V/A。没有新数据的等待仍有原有采样时限，停止指令保持响应。分流测流查询电压，随后按分流阻抗换算电流。

配置阶段**不发 `RANG?`、`NPLC?`、`CMDSet?`、`TRIG:SOUR?` 或 `SYST:ERR?`，不因仪表自动选了较大档位而报 mismatch**。读数仍是实际 V/A，不按所选量程额外乘除倍率。正常通信失败、持续无有效读数、异常拟合增益等原有检查不取消。

命令集在测量后保持 RIGOL，不自动恢复此前的 AGILENT/FLUKE 设置；若之后用别的软件控制此表，应选择其需要的命令集。不会向 DM858 发送 `CMDSet` 或上述 DM3068 专用配置。

### 13.3 量程和输出幅值

| 功能 | DM3068 手册档位 | 本程序选择 |
| --- | --- | --- |
| AC 电压 | 0.2、2、20、200、750 V | 选择覆盖目标的档位；57.735/60/110 V 使用 200 V |
| DC 电压 | 0.2、2、20、200、1000 V | ±100 V 使用 200 V；电压零点使用 2 V 留余量 |
| AC/DC 电流 | 200 μA、2 mA、20 mA、200 mA、2 A、10 A | 直测优先使用 2 A，目标超过 2 A 时使用 10 A；零点也使用 2 A |
| 分流电阻测流 | 使用上述电压档 | 按 `电流 × 分流阻抗` 选档；0.5 A × 0.075 Ω = 0.0375 V，选择 0.2 V |

**原生量程参数是编号：** 电压 0/1/2/3/4 分别表示 0.2/2/20/200/最高档 V；电流 0/1/2/3/4/5 分别表示 200 μA/2 mA/20 mA/200 mA/2 A/10 A。程序直测电流只发送编号 4 或 5，避免误把物理值 `2` 发成原生编号 2（20 mA 档）。`CONF:CURR:AC 2` 与 `MEAS:CURR:AC 2` 不等价。

直接测流不使用小电流档，是为了避免在安培级校准过程中切到 250 mA 保险丝的小电流路径。量程设置不是输出设定：选择 2 A/10 A 档不会让 FPGA 输出 2 A/10 A。默认四步电流校准仍是 0.5 A RMS、0 A、+0.5 A、−0.5 A；九点校验最大设定仍为 2 A，不能把它理解为硬件异常时绝不会超流的保证。

多频点默认电流参考仍为 0.5 A RMS；直测的原 7 A 软件边界也适用于 DM3068，不因仪表有 10 A 档而放宽。手册规定超过 7 A 的通断时限，默认流程不接近该水平。另需注意：DM3068 的 2 A/10 A 交流档在 1 kHz 以上给出的是典型指标，多频点校准不等于仪表不确定度消失。

## 14. DM3068 实测反馈：零有效样本与 Remote 状态

首次现场反馈：电流实际有输出，仪表显示 0、退不出 Remote，最后提示 `Too few valid samples: 0 < 5`。当时信息不能确认是查询超时、仪表真的返回了 0、超量程/非法响应，还是实际选中的测量功能与接线不一致。后续电流、电压日志已确认 `:READ?` 超时，见第 15 节。第 13 节的模拟通过仅证明所测软件路径，不等于实机采样已经验证成功。

`Remote/Rmt` 是远程控制状态，本身不是死机证据。[DM3068 官方用户手册](https://download.rigol.com/en/Manual/Digital%20Multimeters/DM3068/DM3068_UserGuide_EN.pdf) 第 1-6 页说明可按 `Single/Local` 返回本地控制。程序持续查询时可能再次进入远程模式，这是待现场确认的解释，不是本次已证实的冻结原因。

### 14.1 已确认的代码问题与本次处理

- 之前交流测量返回 0 会被过滤、通信/解析错误会被捕获，但最后统一只报告 `0 < 5`，丢失判断根因需要的信息。现在日志和前端错误包含型号、API 通道、`mode`、实际配置指令、查询指令、最后原始响应、交流零/非正读数数量和最后异常。
- DM3068 查询失败后，继续重复发 `READ?` 可能向尚未完成的查询追加请求。现在发生此类通信异常就关闭功放、关闭本次 VISA 会话，当前点不提交；下次开始重新连接。即使失败前已有 5 个读数，也不把这个通信失败的点当作成功。其余机型的原采样重试路径不变。
- 不把 0 当作正常交流校准样本，不降低最少 5 个有效样本要求；不调整功放输出、校准系数、测量量程或既有命令集。关闭 VISA 会话不保证仪表立刻退出 Remote，也不能代替实机故障排查。

### 16.2 已验证的配置和读取流程

依据 [Keysight 34410A/11A/L4411A 官方用户指南](https://www.keysight.com/us/en/assets/9018-05586/user-manuals/9018-05586.pdf)，并在已接入的 34410A 上逐项执行验证。34410A 使用原生 SCPI，不发送 DM3068 的 `CMDSet`、`FUNC/MEAS` 或就绪位查询。

```text
:CONF:VOLT:AC 100
:SENS:VOLT:AC:BAND 20
:TRIG:SOUR IMM
:TRIG:COUN 1
```

**正式校准配置阶段不查量程、不查 NPLC、不查错误队列，也不作严格匹配。** 本次排查脚本读取 `RANG?`、`SYST:ERR?` 只是为了验证命令，不属于上线后的额外拦截条件。正常通信失败、无有效样本及异常拟合增益仍然报错；34410A 查询发生通信异常时立即关输出、关闭会话并丢弃当前点，不反复堆积未完成的查询。

### 18.1 与 34410A 共用的测量流程

依据 [Keysight 官方 Truevolt 操作、编程与维修指南](https://www.keysight.com/us/en/assets/9018-03876/service-manuals/9018-03876.pdf) 中的 `CONFigure:CURRent`、`SENSe:CURRent:AC:BANDwidth`、`SENSe:CURRent:DC:NPLC` 等命令条目核对。对本项目使用的 AC/DC 电压、电流采集，34461A 可以复用现有 34410A 的 SCPI 流程；这不表示所有仪表功能和输入端子都相同。

程序使用固定量程 `CONF`、交流每功能带宽 20 Hz / 直流 10 PLC、立即触发、一次触发一次采样、自动触发延时，再以 `READ?` 获取物理 V/A 读数。读写使用 LF 终止符，沿用原 5 秒通信超时和稳定等待。无需 RIGOL 的命令集切换或就绪位查询，不增加配置回读匹配、错误队列拦截、电压升档或重试机制。

`*IDN?` 厂商为 Keysight 或 Agilent 且型号为 `34461A` 时自动识别。前端仍使用原 `autoCal` 的认证、`start`、`verify`、`stop`、`ch`、`currMode` 和频点字段。旧 DC/50 Hz 四步校准、九点校验、多频点校准/校验均已接入；保存的频率表会记录真实型号 `34461A`，不伪装为 `34410A`。未顺带将 `34465A`、`34401A` 或不同产品 `DM34461A` 纳入已验证型号。

### 18.2 直测电流接 3 A 端，而不是独立的 10 A 端

34461A 有独立的 10 A 输入路径。官方 `CONFigure:CURRent` 条目明确：指定不超过 3 A 的量程会选用 3 A 端子，指定 10 A 档才选用 10 A 端子。因此本次直接沿用 34410A 的 3 A 测量范围；这是本程序当前适配范围，不是说 34461A 本身只能测 3 A。

- `currMode=1` 直测电流：接标有 **3 A 的电流端和 LO**，并确认 Front/Rear 开关与实际接线一致。即使仪表此前选在 10 A 路径，程序发送的 `CONF:CURR:AC/DC 0.1/1/3` 也会选回 3 A 路径。不要接着 10 A 插孔启动这套流程，否则可能读不到实际电流。
- `currMode=0` 分流测流：万用表接分流器电压端，程序使用电压功能并换算电流，不走 3 A 输入路径。
- 默认电流校准设定仍为 0.5 A RMS、0、+0.5 A、−0.5 A；九点校验最大设定仍为 2 A。自定义多频点直测参考沿用 3 A 软件上限，不因为换成 34461A 就提高输出或自动切换到 10 A 端。不得带电换接线。

电压初始量程、零偏处理及电压读数的物理单位均不改变。没有恢复此前已撤回的超量程升档改动，也不修改 FPGA 输出、幅值/RMS 换算、拟合算法、校准文件格式或升级程序。

### 18.3 本次验证

新增独立的 34461A 模拟仪表，包含从遗留 10 A 端子状态切回 3 A、命令和量程检查、禁止额外配置查询、单次读数、超时停止。通过真实前端命令入口与模拟输出帧完成电流四步校准→九点校验、多频点校准→复测保存；另覆盖电压拟合、27 个电压/电流/分流九点校验点、3 A 边界及型号识别。

全部 **174 项 unittest 通过**。以增加 34461A 前的 Git 暂存版本为基线，对 DM858、DM858E、DM3058、DM3058E、DM3068、34410A 和未知旧仪表进行 **16128 组**命令生成、配置写入和读取路径对照，结果一致。静态检查通过。此次没有实际连接 34461A、启动功放、修改实测校准参数或编译发布；第 16 节的 34410A 实机结果不能当作 34461A 实机验证结果。
